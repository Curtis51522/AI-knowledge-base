## S2 — Demand Forecasting (XGBoost)

**File**: `api/module2_forecast.py`

### Architecture
- **6 XGBoost quantile regression models** — one per bakery product
- Models stored in `models/xgboost/<product>_model.json`
- **ThreadPoolExecutor** (max_workers=2) for non-blocking inference
- **Forecast cache**: OrderedDict, TTL 1 hour, max 100 entries
- **Lag feature cache**: 5 min TTL, DB-backed daily sales aggregation

### Feature Engineering
- `build_forecast_features()`: 15 features from config FORECAST_FEATURE_COLS
- Calendar: day_of_week, is_weekend, day_of_month, month, is_public_holiday (Malaysia), is_ramadan (Hijri conversion)
- Weather (from VisualCrossing API): temperature, rainfall, humidity, weather type one-hot
- Historical: lag_1, lag_7, rolling_7d_mean (from `inventory_transactions` outflow)

### Forecast Logic
- Monday (weekday=0) → output 0 demand (shop closed)
- Prediction intervals: `[pred - MAE, pred + MAE]` from `test_metrics.json`
- Confidence tiers: today → "today", day 1-2 → "high", day 3-5 → "medium", day 6-7 → "low"

### API Endpoints
| Method | Path | Description |
|--------|------|-------------|
| GET | `/s2/forecast` | Get forecast (cached, 7 days) |
| GET | `/s2/forecast/refresh` | Force-refresh bypassing cache |
| GET | `/s2/accuracy` | Return per-product test MAE |
| GET | `/s2/sales_history` | Last 200 outflow transactions |

### Training
- `api/train_quantile.py`: Trains XGBoost on synthetic data or DB sales
- `models/xgboost/test_metrics.json`: Per-product MAE/MSE for prediction intervals

- **2 time slots**: 06:00-13:00, 12:00-19:00 (7h each)

- **10 employees**: E001-E010 (Ali, Mei, Raj, Siti, Ahmad, Priya, Kumar, David, Chen, Fatima)
- Dual-role support: Raj (barista+cashier), Ahmad (baker+deputy manager)

### Demand-Driven Staffing
- Reads S2 forecast → determines demand_level (high/normal/low) per day
- Staff required per role = f(forecast, COFFEE_DEMAND_RATIO)
- Deputy manager: fills manager gap when manager off-shift

### Constraints
- Max 1 shift/day per employee
- Min/max weekly hours
- Unavailable dates (sick leave, rest days)
- Role coverage minimums
- Fairness: hour gap ≤ 8h within same role
- Past-date locking (no retroactive changes)

## Data Flow: Complete Transaction

```
1. Login → JWT issued (S4/auth)
2. Scan tray → YOLO detects products (S1)
3. POS renders detections with stock levels (S4 frontend)
4. User confirms/edits → items added to cart
5. Generate Top-3 bundles → S4/combo scores bread-coffee pairs
6. AI Sales Script → S5 generates upselling script
7. Checkout → S4/checkout/complete:
   a. Deduct bakery via FIFO (S1)
   b. Record coffee as outflow (S4)
   c. Generate receipt (stored in receipts table)
8. Freshness update runs every 30 min (S1 freshness_service)
9. S5 monitor runs every 5 min (alerts)
```

| `receipts` | id (PK), receipt_id (UNIQUE), items (JSON), subtotal, discount_total, total, savings |

### Freshness Model
- **Fresh**: same calendar day → full price, green tray
- **Day-1**: next day → 20% off, yellow tray
- **Expired**: 2+ days → recorded as waste, deleted from inventory
- Switches at **midnight** (not 24 hours from production)
